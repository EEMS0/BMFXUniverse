# Merchandise integration

The shop lives at `/merch` (`src/app/merch/page.tsx`). It shows the EEMS merch artwork (with a zoom and magnifier) and the live **EEMS merch** collection through Shopify's Buy Button SDK (`src/components/merch/ShopifyCollection.tsx`). The old address `/merch.html` redirects to `/merch` (a permanent redirect on Vercel, set in `next.config.ts`; `public/merch.html` covers static hosts).

Every "Shop merch" link on the site points at this page. Links to it are plain page loads, so Shopify's scripts and cart only ever run on the merch page.

## Store details

- Store: `rfrjfs-u0.myshopify.com`
- Collection: **EEMS merch**, ID `695390503244`
- Shopify admin: https://admin.shopify.com/store/rfrjfs-u0/collections/695390503244
- All settings are in `src/content/merch.ts`.
- Products, variants, prices and availability are loaded live from Shopify. To list a new product, add it to the collection and make it available to the Buy Button sales channel; no website change is needed.
- The Storefront token in `merch.ts` is the public token generated by the Buy Button editor and is meant to be in page code. Never replace it with an Admin API token (those start with `shpat_`).
- Checkout happens on Shopify; the website never receives payment details.

## Look and layout

The Buy Button renders inside its own frames, so the site's colours and fonts are passed to it as `styles` in `ShopifyCollection.tsx`. Products show two per row on phones and three on wider screens.

Shopify writes each `@media` block before the matching base rule, so a property that changes with screen width must only appear inside the media blocks (`phone` / `wide`), never in the base style as well — otherwise the base value always wins.

If the SDK can't load (offline, blocked, or Shopify down), the page says so and offers **Try again**. Without JavaScript it explains that the shop needs JavaScript.

## Launch verification

Check mobile and desktop product rendering, colour and size selection, cart totals, and the transition to checkout. Confirm a payment provider is fully activated and that shipping profiles cover the intended destinations. A checkout visit without submitting payment does not verify order fulfilment.

Tapstitch fulfilment settings and billing must be checked in Tapstitch. Preserve its product and variant mapping when editing Shopify products. Confirm fulfilment with an explicitly authorised test order before treating fulfilment as verified.

## Tests

The end-to-end tests never load the real SDK: `tests/e2e/fixtures.ts` replaces it with a small stand-in, so tests don't depend on the live store or create carts.
